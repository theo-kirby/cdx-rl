That is a claim worth being explicit about, because criterion 6 rests on it:
`cadex_train.py` builds its optimiser with `learning_rate = float(options.learning_rate)`
as a **constant**, hand-rolled Adam with no schedule — nothing anywhere reads
the total iteration count. So seed 0's first 1 500 iterations are generated by
exactly the same recurrence as 200109's first 1 500, and stopping earlier
cannot change them.

## One thing already visible at iteration 0

Seed 0 is the replication control, and it does **not** reproduce 200109
bitwise:

| | 200109 | this run |
|---|---|---|
| `reward_per_step` | −0.9412031 | **−0.940929** |
| `loss` | 134.64029 | **134.573** |
| `episode_steps` | 85.333 | **85.2** |
| `action_std` | 0.4001988 | 0.4002 |

Same seed, same `trainer_sha256`, same hyperparameters, same card — and the
**very first** iteration already differs in the fourth significant figure.
This is not drift from a shared start; there is no shared start.

MJX and XLA reductions on a GPU are not bitwise reproducible run to run, and
PPO is a feedback loop that amplifies. §7 criterion 6 anticipated exactly
this and said it is *a finding about run-to-run comparability on this card,
not a failure of the experiment* — but it means the seed-0 comparison is a
question about **shape**, not identity, and §8 must read it that way.

Recorded here, before the curves existed, so that reading it that way later
cannot be mistaken for an excuse constructed after the fact.
